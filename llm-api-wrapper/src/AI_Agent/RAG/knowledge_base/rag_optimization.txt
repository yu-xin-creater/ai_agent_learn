RAG 系统优化策略详解

一、文本分割优化

1. 递归字符分割（Recursive Character Splitting）
这是最常用的分割方法。它按照分隔符的优先级递归地分割文本，优先保持段落完整，其次保持句子完整。分隔符优先级通常为：段落分隔符 > 换行符 > 句号 > 空格 > 单字符。

2. 语义分割（Semantic Splitting）
利用 Embedding 模型判断相邻句子的语义相似度，在语义变化较大的位置进行分割。这样可以确保每个文本块内部的语义连贯性。

3. 分割参数调优
- chunk_size（块大小）：通常设置在 200-1000 字符之间。太大会引入噪声，太小会丢失上下文。
- chunk_overlap（重叠大小）：通常设置为 chunk_size 的 10%-30%。重叠可以确保跨块的信息不会丢失。

二、检索优化

1. 查询改写（Query Rewriting）
用户的原始问题可能表述不清或过于口语化，通过 LLM 将查询改写为更适合检索的形式。例如将"RAG怎么用"改写为"RAG检索增强生成的使用方法和实现步骤"。

2. 多查询检索（Multi-Query Retrieval）
从多个角度生成查询变体，分别检索后合并结果。这样可以提高召回率，减少因表述方式导致的遗漏。

3. 混合检索（Hybrid Search）
结合向量语义检索和传统关键词检索（如BM25）。语义检索擅长理解同义表达，关键词检索擅长精确匹配专有名词。两者互补可以提高检索质量。

4. 最大边际相关性（MMR, Maximal Marginal Relevance）
在检索结果中平衡相关性和多样性。避免返回大量内容相似的文档片段，确保结果覆盖更多角度。

5. 重排序（Reranking）
使用专门的重排序模型（如 Cohere Rerank、BGE-Reranker）对初步检索结果进行精细重排。重排序模型通常比向量相似度更准确，因为它可以同时看到查询和文档。

三、生成优化

1. 上下文压缩（Context Compression）
对检索到的文档进行压缩，只保留与问题直接相关的信息，去除无关内容。这样可以减少噪声、节省 token、提高回答质量。

2. 引用溯源（Citation）
在生成的回答中标注信息来源，例如 [来源1]、[来源2]。这提高了答案的可信度，用户可以直接查看原文验证。

3. 思维链（Chain-of-Thought）
引导 LLM 先分析检索到的内容，再逐步推理得出答案。这在复杂问题上可以提高答案质量。

4. 自我反思（Self-Reflection）
让 LLM 检查自己生成的答案是否与检索内容一致，是否存在幻觉或矛盾，如有则重新生成。

四、评估指标

1. 检索质量评估
- 召回率（Recall）：相关文档被检索到的比例
- 精确率（Precision）：检索结果中相关文档的比例
- MRR（Mean Reciprocal Rank）：第一个相关结果的平均排名倒数

2. 生成质量评估
- 忠实度（Faithfulness）：回答是否基于检索内容，无幻觉
- 答案相关性（Answer Relevancy）：回答与问题的相关程度
- 上下文精确率（Context Precision）：使用的上下文是否都是相关的

3. 常用评估框架
- RAGAS：专门用于 RAG 系统评估的框架
- TruLens：LLM 应用的评估和追踪框架
