# RAG（检索增强生成）技术介绍

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与文本生成相结合的技术架构。它通过在生成答案之前先从外部知识库中检索相关信息，从而让大语言模型能够基于最新、最准确的信息来回答问题。

## RAG 的核心思想

传统的大语言模型（LLM）仅依赖训练数据中的知识来生成回答，存在以下问题：
1. 知识截断：模型只知道训练时的信息，无法获取最新知识
2. 幻觉问题：模型可能编造不存在的信息
3. 领域局限：对于特定领域的专业知识了解有限

RAG 通过"先检索、再生成"的方式解决这些问题：
- 将用户的问题转化为向量
- 在外部知识库中检索最相关的文档片段
- 将检索到的内容作为上下文，与问题一起输入给 LLM
- LLM 基于提供的上下文生成有据可循的回答

## RAG 的工作流程

### 离线阶段（Indexing）
1. **文档加载**：从各种来源加载文档（PDF、网页、数据库等）
2. **文本分割**：将长文档切分为小的文本块（chunks）
3. **向量化**：使用 Embedding 模型将文本块转换为向量
4. **存储索引**：将向量存入向量数据库，建立索引

### 在线阶段（Querying）
1. **查询向量化**：将用户问题转换为向量
2. **相似度检索**：在向量库中找到最相似的文档块
3. **上下文组装**：将检索到的文档块组装成 Prompt 上下文
4. **答案生成**：LLM 基于上下文生成答案

## RAG 的优势

1. **知识时效性**：可以随时更新知识库，无需重新训练模型
2. **减少幻觉**：回答基于真实的文档内容
3. **可追溯性**：可以标注信息来源，方便验证
4. **成本低**：相比微调(Fine-tuning)，RAG 不需要重新训练模型
5. **灵活性**：支持多种数据源和文档格式

## RAG vs Fine-tuning

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| 知识更新 | 更新知识库即可 | 需要重新训练 |
| 成本 | 低（仅推理成本） | 高（训练成本） |
| 准确性 | 基于源文档，可验证 | 依赖训练质量 |
| 适用场景 | 知识密集型问答 | 风格/格式调整 |
| 延迟 | 略高（多了检索步骤） | 低 |
