嵌入模型（Embedding Model）详解

一、什么是文本嵌入

文本嵌入（Text Embedding）是将文本映射到高维向量空间的过程。嵌入模型能够捕捉文本的语义信息，使得语义相近的文本在向量空间中距离更近。

例如："猫"和"喵星人"虽然字面不同，但在向量空间中会很接近，因为它们表达相同的含义。

二、嵌入模型的工作原理

1. 输入处理：将文本分词为 token 序列
2. 编码：通过 Transformer 网络对 token 进行编码
3. 池化：将所有 token 的表示聚合为一个固定长度的向量（如平均池化、CLS池化）
4. 归一化：对向量进行 L2 归一化

三、主流嵌入模型

1. OpenAI text-embedding-3-small
- 维度：1536
- 特点：性能好、API简单
- 价格：$0.02/1M tokens
- 适用：英文为主的通用场景

2. OpenAI text-embedding-3-large
- 维度：3072（可降维）
- 特点：OpenAI最强嵌入模型
- 价格：$0.13/1M tokens
- 适用：对精度要求高的场景

3. 通义千问 text-embedding-v3
- 维度：1024（默认）
- 特点：中英文效果好、支持多维度
- 价格：约 0.0007 元/1000 tokens
- 适用：中文为主的应用

4. BGE 系列（BAAI）
- bge-small-zh-v1.5：维度 512，轻量级中文模型
- bge-base-zh-v1.5：维度 768，中等中文模型
- bge-large-zh-v1.5：维度 1024，大型中文模型
- bge-m3：维度 1024，多语言多功能模型
- 特点：开源免费、可本地部署
- 适用：对数据隐私要求高、需要本地部署

5. Jina Embeddings v2
- 维度：768
- 特点：支持 8192 token 长文本
- 适用：长文档嵌入

四、选型建议

1. 优先考虑的因素：
- 语言支持：中文场景选择中文优化模型
- 部署方式：是否需要本地部署
- 成本预算：API调用 vs 本地推理
- 精度要求：任务对精度的敏感度

2. 推荐方案：
- 中文通用场景：通义千问 text-embedding-v3（API）或 BGE-base-zh（本地）
- 英文通用场景：OpenAI text-embedding-3-small
- 多语言场景：BGE-M3（本地）或 text-embedding-3-large（API）
- 低成本方案：BGE-small-zh + 本地部署

五、使用技巧

1. 批量处理
- 将多条文本组成批次一起调用，减少 API 请求次数和网络延迟

2. 文本预处理
- 去除无关的特殊字符和格式信息
- 保留关键的语义信息

3. 缓存策略
- 对相同文本的嵌入结果进行缓存，避免重复计算
- 使用文本哈希作为缓存键

4. 向量维度选择
- 维度越高通常精度越好，但存储和计算成本也越高
- 在精度和效率之间找到平衡点

5. 模型一致性
- 构建知识库和查询时必须使用同一个嵌入模型
- 不同模型产生的向量不具有可比性
